# TOTP + single-use Recovery Code replaces Google SSO, single-operator

The system is now single-operator — `Super Admin` (Neranjan) is the sole user, so `Allowed Email`/Google SSO (`CONTEXT.md:67` pre-0009, `lib/authAccess.ts:182` `canGoogleUserSignIn`) is deleted. Auth is **password (bcrypt, not SHA-256 `lib/authAccess.ts:25`) + TOTP** via Google Authenticator (RFC 6238, 30s step, ±1 window, 20-byte base32 secret) on every login after one-time enrollment. The secret is encrypted at rest with AES-256-GCM (`TOTP_ENCRYPTION_KEY` env) in `super_admin.totp_secret_encrypted`, never in `localStorage`.

For TOTP loss, a **single-use 64-char (256-bit) Recovery Code** (`crypto.randomBytes(32)` hex, grouped `8×8`, bcrypt hash) is generated once at enrollment, displayed once with mandatory "I have saved it" + download, then never shown again. Entered at `/recovery` it bypasses both password and TOTP, creates a 10-minute recovery session that forces immediate password reset, TOTP re-enrollment, and new code generation; the used hash is burned. This avoids email fallback (removed with SSO) while preventing a reusable super-key. `Session` is now 30-day absolute plus 7-day idle sliding timeout (`app/api/auth/route.ts:7` was 7d absolute) via `httpOnly Secure SameSite=Lax` cookie bound to `sessions(token, expires_at, last_active_at)`, revoked on any password/TOTP/recovery reset or 7d inactivity, with `Landing Gate` exempting only `Landing` and `/recovery`.
